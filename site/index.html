Norm FDE

Turn AI coding agents into digital employees that deliver

Say what you want in plain language. Norm writes it into a checkable Brief, builds only that scope, and calls it delivered only after review and acceptance pass.

Delivery

It runs the delivery itself

You talk; the digital employee runs the process.

  1. Brief

    Goal / out of scope / checkable acceptance

  2. Implement

    Only the Brief scope, on its own branch and worktree

  3. Review

    Ponytail review; only Ship passes

  4. Accept

    Checked against acceptance and test rules; not done until met

  5. Hand off

    One-line result; revise if it is not right

In your editor

Just ask in your editor

Install once, then talk in Cursor or Claude Code.

  • No commands to learn

    No slash commands, no Spec phases to run yourself.

  • Clarify before coding

    Your ask becomes what to build, what not to build, and how we know it is done.

  • Done means accepted

    It claims finished only when acceptance checks out, not when code merely exists.

  • Code review gate

    Smallest complete change. Without a passing ponytail-review, norm check and the stop hooks reopen the job.

  • PR modeopt-in

    Every job merges through a GitHub PR: CI failures go back to the employee, and it auto-merges when green.

  • Clear branches

    main for production, develop day to day; every job in its own worktree.

Digital employees

Three roles

All run as Cursor Agent or Claude Code; the task role decides who does what.

  • Implementer

    Does
    Builds to acceptance; updates the product README; starts the preview and stamps delivery
    Does not
    —

  • Functional regression

    Does
    Runs deterministic regression against acceptance (Playwright, npm test, …); adds missing tests, runs them, keeps evidence
    Does not
    Change product scope; stamp accepted when tests fail

  • Deployer

    Does
    Publishes to the planned host and writes the public URL into the delivery preview
    Does not
    Change product scope
