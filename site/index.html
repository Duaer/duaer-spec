Delivery

它自己会跑完交付

你只要说话，流程由数字员工执行。

  1. Brief

    目标 / 不做 / 可检查验收

  2. 实现

    只做 Brief 范围，独立分支与 worktree

  3. 评审

    Ponytail 评审，只有 Ship 才放行

  4. 验收

    对照验收与测试规则，未满足不算完成

  5. 交接

    一行结论；不满意再改一版

In your editor

在编辑器里交代就行

装一次，在 Cursor 或 Claude Code 里用平常话说。

  • 不用记命令

    不用 slash 命令，也不用自己点「写 Spec / 拆任务」。

  • 先谈清楚再动手

    整理成要做什么、不做什么、怎样算做完。

  • 做完才算完

    对照验收通过才说「交付好了」，半成品不会假装完成。

  • 评审闸门

    最小的完整改动；没过 ponytail-review，norm check 和收尾钩子都会打回。

  • PR 模式可选

    每个任务走 GitHub PR：CI 失败退回修，全绿自动合并。

  • 分支规矩

    main 上线、develop 日常；每个任务一个独立 worktree。

Digital employees

三种角色

运行时都是 Cursor Agent 或 Claude Code，按任务角色分工。

  • 实现员工

    干什么
    按验收写功能；更新产品 README；把预览跑起来并 stamp 交付
    不干什么
    —

  • 功能回归

    干什么
    对照验收做确定性回归（Playwright、npm test 等）；缺测就补测、跑通、留证据
    不干什么
    不改业务功能范围；测挂了不擅自 stamp「验收通过」

  • 部署员工

    干什么
    按选定平台上线，把公网地址写入交付预览
    不干什么
    不改业务功能范围

Deploy

部署到哪里

开工前在控制台选计划托管平台，部署员工负责上线。

  • 方式适合你要准备
  • 暂不部署只在本地做完无
  • GitHub Pages静态站 / 文档站（默认）GitHub 仓库与 gh 登录
  • CloudflarePages 静态站；Workers 接口API Token 与 Account ID
  • 阿里云OSS（+ CDN）；函数计算AccessKey
  • AWSS3 + CloudFront；Amplify / LambdaAccess Key
